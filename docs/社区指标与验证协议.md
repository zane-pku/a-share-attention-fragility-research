# 社区关注与市场脆弱性研究协议

## 从叙事到可反驳假说

| 假说 | 观察量 | 可推翻的情况 |
|---|---|---|
| H1 注意力扩散 | 多个独立平台的异常资产提及份额、普通讨论触达率同步走高 | 新增关注局限于同源搬运，或控制过去收益后关系消失 |
| H2 方向与关注分离 | 同样高的注意力，在追涨、看空或恐慌状态下有不同未来路径 | 高注意力在上涨和下跌事件中同样常见，或没有稳定的交互 |
| H3 边际买盘衰减 | 高关注叠加新参与增加、上涨面开始收窄、昨日强势股次日承接走弱 | 高关注组存在延续但无随后回撤，或只有少数被挑选的资产下跌 |
| H4 杠杆与交易机制 | 关注扩散乘以融资异常或短线接力衰退 | 联合状态在样本外不提升概率预测，或者结果由同一个波动率冲击解释 |
| H5 平台代表性 | 逐平台、完全覆盖、留一平台分别能否复现 | 信号对某单一排序页面敏感，或平台界面变化前后出现结构断点 |

事前固定 A 股主题、行业、映射生效日期和对照收益。黄金、原油、海外股票、虚拟资产如另做试验，需独立设定交易时钟和基准。不得从昵称、照片或语言推断性别、外貌、婚育、年龄、职业或投资水平。

## 原始观测与计分

1. 固定每个平台可访问入口、查询词、语言市场、时间窗和是否严格时序。账号榜、热门推荐、搜索补录和严格时间流分层。对外分发使用汇总值。首见版本保存发布时间、收集时间、首次进入样本时间和合成时间。
2. 去除转发、广告、资讯号和跨平台近重复。保留纳入数、拒绝数、独立参与者数和未命中日志。对同一作者同一主题日最多记三条，原始作者键只在授权本地处理。被截断或失败的入口标未观测。完成完整区间且无合格话题才确认零条。
3. 一条文本允许有提问、追涨、恐慌多标签。多空互斥，讽刺、转述、引用他人意见和无法解析的标记为未知。对每平台和行情阶段做双人盲标，记录分歧矩阵与时间切分后的精确率、召回率。抽样不得按一个成功案例临时改变。
4. 文本示例的含义依赖上下文。“新手第一天，怎么买”计入提问。“别追高”不计追涨。“某机构唱多，我认为太贵”需要区分引用与作者立场。情绪方向、问题类型和强度分别储存。
5. 对每个平台自身历史计算中位历史分位。脚本原型使用此前 60 个交易日，至少 30 个有效值。当天不进入自身历史标尺。注意力为主题去重提及/同采样框全帖，提问、追涨、恐慌为相关帖子/主题贴，净方向为(多−空)/主题贴。支持已确认零提及且全帖分母为正的 0% 注意力。零主题贴时方向及各语义占比留空。
6. 平台席位固定。每个平台分位以 n/(n+20) 向 0.5 收缩，n 是对应比率分母；建议用真实标注数据比较有效样本数收缩。展示层空席留中心，判断层至少两个有效平台且覆盖席位不少于 50%，保留逐平台时间序列和留一渠道范围。缺测不等于中性真实情绪。热门流不参与注意力份额，只能在同一固定采样框内提供文本表达指标。
7. 扩散因子使用“合格时序平台中异常注意力超过各自 80% 历史分位的平台份额”。每个合格时序平台占固定席位。部分覆盖时输出扩散率上下界，所有合格时序平台同时可得且至少两个时才输出研究值。新人渗透候选使用同一授权可观察样本中首次参与主题作者占比，需 60 个交易日完整回看，明确冷启动造成的虚假新增。
8. 长期维护中按来源版本、标签分类版本和主题映射版本归档。换接口、换入主题股、采样算法变动或语义模型升级时单列断点。历史估算、实时采集和回填三者分开记账。

## 输入与运行

`scripts/community.py` 读取授权聚合 CSV、真实交易日历 CSV 和固定平台配置。它计算 6 条可审计的社区研究序列。文本分词采集、作者去重与本研究尚无历史的数据源，分别由数据提供方和后续实验处理。

| 字段 | 约定 |
|---|---|
| date / topic / platform | 日期为北京时间 YYYY-MM-DD，每组合一行。topic 使用稳定 ID |
| status / mode | observed / verified_zero / unobserved。mode 为 chronological 或 ranked_feed |
| published_at | 当日聚合首版可用时间，必须带时区且晚于或等于当日 00:00、不晚于该日 20:00（北京时间）。原系统需额外留存事件时间和入库时间以追溯首版 |
| mentions / total_posts | 去重后的主题贴数和同口径全贴数。平台内单主题 mentions ≤ total_posts |
| questions / chase / panic / bull / bear | 题材贴中语义命中数。bull、bear 互斥。unobserved 所有计数字段留空 |
| calendar | 一列 date，须为唯一递增的真实交易日，不可用周一到周五规则代替 |

```text
python scripts/community.py --input inputs/community.csv --calendar inputs/calendar.csv --config docs/community.example.json --out outputs/community
```

输出包含 `community_signals.csv` 和 `community_coverage.csv`。默认配置示范四渠道席位，实际采样框及渠道模式需先核验。小红书若只能接触排序流，可作为新配置的文本支线，不能凭它核验声量或零帖；要测全站扩散，需要固定检索范围、发布时间和可复原的抽样分母。

## 社区实证验收

- 日频宽基以 t+1 收盘为进入时点。行业与资产横截面额外控制行业固定效应、市值、流动性、收益、波动和重大公告。按同方向检验 1/5/20/60 日，首要任务为 20 日标的最大回撤概率，定义和阈值冻结。
- 建议冻结连续的至少 252 个交易日作为首轮可评估样本，留出期至少覆盖一个完整市场阶段。252 日是初始研究门槛，事件数量不足时继续记录。平台之间用同一可比较覆盖样本，报告所有已登记因子及剔除理由。
- 进行仅市场基准、加入单个社媒指标、加入扩散交互三种逐年预报，比较 Brier、对数损失和固定预警频率下的误报/漏报。按事件簇或非重叠区间再检查。报告留一平台、热门流排除、节假日对齐、主题映射冻结、多重检验及当期溢出对照。
- 反向安慰剂将信号日期在同一市场状态内做块置换，避免把自相关当预测力；并分别比较关键新闻日、政策日及日常日期。使用同年度同波动组的随机日期看相似回撤发生率。
- 上游公开样本不足以复跑真实社区历史。代码可验证计算与缺失机制，真实回测还需要经授权、可追踪首见时间和覆盖范围的逐日历史。
